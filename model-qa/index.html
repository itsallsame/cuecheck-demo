Two discrepancies, measured and rechecked

I authored a small reference plan, built a deliberately inconsistent Blender model, recorded the differences, corrected them, then exported and re-imported both revisions to verify the dimensions. All geometry, reference data, annotations and checks in this example are my own work.

This is a synthetic exercise, not a past client project or a finding about INK TO BRICK.

Reproduction and correction

  1. Open the dimensioned reference and source specification. Dimensions are metres.
  2. Open before.blend or import before.glb. Measure the world-space bounds of all six wall meshes. Subtract partition_south's maximum y from partition_north's minimum y for the opening gap.
  3. The before model's east boundary is 0.20 m too far east. Correct the outer-wall extent to 8.00 m. Move the north partition segment's lower end from y=2.60 to y=2.90 m.
  4. Open after.blend or import after.glb and repeat the measurements. The original before evidence remains available.
  5. Run blender --background --python build_and_check.py with the source script and source-spec.json beside it. It writes both revisions, exports GLB, re-imports each into a clean Blender scene, and writes the measured report.

Evidence and limits

The checks use world-space mesh bounds, with a tolerance of 0.001 m. The before model fails width and opening-gap checks; the corrected GLB passes all three. Each GLB round trip preserves these three dimensions within the same tolerance. This demonstrates Blender-to-GLB-to-Blender checks, not interoperability across multiple independent tools.

The plan does not specify the opening head height, so this model leaves an unbounded vertical gap and checks only the plan gap. No lintel, door swing, stairs, multi-floor connectivity, BIM semantics, building-code compliance, structural design or real site measurements are evaluated. No INK TO BRICK editor behavior has been tested.
